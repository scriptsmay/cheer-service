# AI 生成统计参考面板与校验优化设计

## 目标

为 admin AI 配置页提供只读的模型表现参考，并降低流式生成因过严校验导致的失败率。最终模型仍由用户手动选择和保存，系统不自动切换。

## 设计

### 生成尝试记录

新增轻量 `ai_generation_attempts` 集合/表，记录每次流式生成的终态元数据：`request_id`、`model`、`status`、`termination`、`elapsed_ms`、`retry_count`、`validation_failure`、`usage`、`created_at`。不记录用户输入、输出、思考内容、API key、Authorization、完整 base URL 或原始请求内容。

成功、校验耗尽、生成错误、deadline/idle timeout 路径都写入一次终态记录。成功报告 `ai_reports` 保持原有业务记录职责；尝试记录独立存在，避免把失败报告混入成功报告统计。

### Admin API

新增 `GET /api/admin/ai/stats?window=24h|7d|30d`，沿用 admin 鉴权，只读查询指定时间窗口内生成尝试记录，按 `model` 聚合：样本数、complete 数、成功率、P50/P95 耗时、重试数、校验失败原因计数、token usage。空数据返回空数组；非法窗口返回标准参数错误。

### Admin 面板

在现有 AI 服务配置区域下方增加只读统计区域，支持 24h/7d/30d 切换。展示模型、样本数、成功率、P50/P95、重试数、校验失败和 token usage；样本不足时显示数据不足提示。模型下拉框和保存/测试操作保持原样，不增加自动选模或自动写入配置行为。

### 校验优化

保留 JSON 解析、配置条数、每条至少 10 字、允许数字白名单和内容安全等硬规则。仅调整两类误杀：

1. 重复开头：继续拒绝与历史开头指纹完全相同的输出，但不再把常见短前缀或相同首字符直接判为失败。
2. 数字：把赛事阶段、日期上下文锚点和已有 refs 中的数字纳入允许集合；其他未知数字仍返回 `ungrounded_number` 并触发带具体原因的重试指令。

重试指令使用与持久化统计一致的 reason 词汇，不输出完整失败输出。

## 验收

- 新增/修改后端测试通过，全量后端测试无回归。
- admin 统计接口覆盖时间窗口、聚合、鉴权和空数据。
- admin 页面只读展示统计，现有模型手动配置流程不变。
- 线上采集 10 个样本，确认无平台 300 秒硬杀、P95 小于 180 秒，并记录实际成功率与失败原因分布。
